Quality Assurance

How I check that software works

Test case design

I turn requirements into clear test cases with steps and expected results.

Functional testing

I test each feature by hand against its requirements, including invalid input.

Regression testing

After a fix, I re-run earlier tests to confirm nothing else broke.

Bug reporting

I write reports with steps to reproduce, expected and actual results, and severity.

Example test case format

A sample of how I structure test cases for a login feature.

ID Scenario Steps Expected result
TC-01 Login with valid details Enter a registered email and password, then click Login User is taken to their dashboard
TC-02 Login with a wrong password Enter a registered email and a wrong password An error message appears and the user stays on the login page
TC-03 Submit empty fields Leave both fields blank and click Login Validation messages show for each required field
Found→ Reported→ Fixed→ Retested→ Closed
